# Build Spec — AgentLedger v0.3.1: Scarcity Window + Dogfood Telemetry (Tier-2)

**Date:** 2026-09-09
**Status:** DRAFT — execute only after Morgan verdict on v0.3 AND v0.3 deployed to Railway
**Sources:** launch-kit patterns 4-5 (scarcity window, dogfood-as-trust)

## Item 1 — Scarcity window: first-50 claims get Pro free for 1 year
- New mechanic: first 50 distinct agent_ids that claim a slot (first write) get `pro_until = now + 365d`
  stored per agent (new column `pro_until` on agents table, additive migration).
- `ensure_agent_secret()` stamps pro_until on claim when global claimed-count (all-time) < 50.
- Cap behavior for pro agents: budget cap lift — pro agents exempt from the 3-agent free tier rules
  (existing beta cap logic extended: check pro_until before rejecting with BetaCapExceededError).
- Expose in responses: agents report includes `plan: free|pro_scarcity|pro_stripe`, `pro_until`.
- Telemetry events: `pro_scarcity_claimed` (with remaining count), `pro_scarcity_exhausted` (when 50th fires).
- /stats + /v1/metrics surface `scarcity_claims_left` (public number drives urgency; do not expose emails).
- README/status: "First 50 agents get Pro free for 1 year — N left" badge line (server-rendered).

## Item 2 — Dogfood telemetry (AgentLedger tracking AgentLedger)
- Cron job (Hermes side, not repo): daily `agent-ledger-dogfood` — track our own infra spend via REST:
  Railway bill (manual rail), Ollama Cloud token spend (from weekly cost rollup), x402 calls.
- First dogfood entry doubles as the claim-on-first-write smoke test in production.
- Landing hero: "AgentLedger tracks its own infra spend" — real numbers from /stats once data exists.

## Acceptance criteria
- [ ] 51st claim does NOT get pro_until; first 50 do; regression tests for both
- [ ] pro agent beyond free cap can still write (budget rules intact for free agents)
- [ ] scarcity_claims_left accurate in /stats; no PII in any new output
- [ ] Existing 52 tests still pass + new tests green
- [ ] Dogfood cron registered, first entry recorded

## Constraints
- Additive schema only; no change to agent_secret claim semantics; version stays 0.3.0 on wire (patch release 0.3.1 in server.json only)
- Privacy: aggregate counts public, never emails/agent_ids
